# Rename "buckets" to "cutouts" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the second lesson variant from "buckets" to "cutouts" throughout the entire repo, and reframe lesson content so the default cutouts workflow is loose-on-table (no grouping required), with bucket-grouping demoted to an optional extension.

**Architecture:** The variant system has three layers: a Svelte store with a `Variant` type, a `data-variant` HTML attribute set in `BaseLayout`, and per-lesson `<Variant is="...">` MDX wrappers. We rename the value (`"bucket"` → `"cutouts"`), then propagate to file names, component names, type names, CSS class names, hero images, and lesson copy. A one-shot localStorage migration silently upgrades existing `"bucket"` entries. Lesson MDX content is rewritten so the cutouts variant describes loose tokens on a table; the bucket-grouping workflow becomes an "Optional extension" subsection where it appears.

**Tech Stack:** Astro + Svelte 5 + MDX, Typst (handouts and CLI templates), Rust (CLI tool), TypeScript, Vitest, pnpm.

**Worktree (recommended):** This is a wide-ranging rename across ~50 files. Suggest creating a worktree with `git worktree add ../llms-unplugged-cutouts -b rename-buckets-to-cutouts` before starting.

```typescript
export type Variant = "grid" | "cutouts";

const STORAGE_KEY = "llms-unplugged-variant";
const DEFAULT_VARIANT: Variant = "grid";

function loadVariant(): Variant {
  if (typeof window === "undefined") return DEFAULT_VARIANT;
  try {
    const stored = localStorage.getItem(STORAGE_KEY);
    if (stored === "grid" || stored === "cutouts") return stored;
    if (stored === "bucket") {
      localStorage.setItem(STORAGE_KEY, "cutouts");
      return "cutouts";
    }
  } catch {}
  return DEFAULT_VARIANT;
}

let variant = $state<Variant>(loadVariant());

if (typeof window !== "undefined") {
  window.addEventListener("storage", (e) => {
    if (e.key === STORAGE_KEY && (e.newValue === "grid" || e.newValue === "cutouts")) {
      variant = e.newValue;
    }
  });
}

export function getVariant(): Variant {
  return variant;
}

export function setVariant(v: Variant) {
  variant = v;
  if (typeof window !== "undefined") {
    try {
      localStorage.setItem(STORAGE_KEY, v);
    } catch {}
  }
}

export function toggleVariant() {
  setVariant(variant === "grid" ? "cutouts" : "grid");
}

export function isGrid(): boolean {
  return variant === "grid";
}

export function isCutouts(): boolean {
  return variant === "cutouts";
}
```

```typescript
import type { BigramModel } from "./tokens";

export interface CutoutsForLabel {
  label: string;
  tokens: string[];
}

export function buildCutoutsFromModel(vocabulary: string[], model: BigramModel): CutoutsForLabel[] {
  const cutouts: CutoutsForLabel[] = [];

  for (const word of vocabulary) {
    const row = model.counts.get(word);
    if (!row) continue;

    const tokensForLabel: string[] = [];
    for (const [to, count] of row.entries()) {
      for (let i = 0; i < count; i++) {
        tokensForLabel.push(to);
      }
    }

    if (tokensForLabel.length > 0) {
      cutouts.push({ label: word, tokens: tokensForLabel });
    }
  }

  return cutouts;
}
```

Note: `CutoutsForLabel` describes the *set of tokens* that share a prefix label — i.e. the candidate tokens you'd find when searching for that prefix. The bucket-as-container metaphor goes away; this is now just a labelled bag of tokens.
