## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Thin vertical slice of the TASK-166 port, to show Tim Bell and the maintainers how it goes before committing to the full port. Decisions and background are in TASK-166. English only, with locale-ready URLs and content layout (no dependency on TASK-101).

The topic is Binary numbers, the one that exercises the most of the stack:

- it is the only topic that uses all four verto tags (panel, image, iframe, video)
- it has 23 of the 32 programming challenges with automated test cases, including both function-call cases (63 stdin/stdout cases besides); only Kidbots has the rest
- it has junior and senior lessons (6), the most curriculum integrations (7), CT links and learning outcomes
- its lessons use generated printables (binary-cards, binary-cards-small, binary-windows, binary-to-alphabet)
- at 251 English Markdown files it is about a third of the whole content port, so the verto conversion gets a real workout

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Local half done on 2026-10-11 in `~/projects/cs-unplugged` (one commit on `main`, not pushed, no remote yet). Its README covers the commands and the design.

## What exists

- 136 pages built from the ported Binary numbers topic: 6 lessons (3 junior, 3 senior), 7 curriculum integrations, 23 programming challenges with their per-language solutions, glossary, 4 printable pages
- every page keeps its Django URL, so only the deprecated unit-plan routes need redirects (`public/_redirects`); checked under `wrangler dev`, where they return 301
- Python editor for the 22 challenges that have a Python implementation, running Pyodide in a Web Worker; pass, fail, syntax error, runtime error and infinite loop all checked in a real browser
- `/en/search/` on Pagefind with a content-type filter
- 68 PDFs (17 MB) for the four Binary numbers printables, generated by the upstream generator classes with no Django server or database, in about 40 s
- `pnpm run check` and the build's accessibility and link checks all pass

## Findings

- the content port was mechanical: 274 Markdown files converted with no hand edits. MDX needed `<br>` closed and `<` escaped, nothing else
- upstream data problems the port surfaced: a duplicate key in learning-outcomes.yaml, a `{panel type="teachering"}` typo, a `#Heading` with no space, and heading levels that skip (fixed at build time, content untouched)
- the two function-call test cases are placeholder data (`hello("Test")`) on a Scratch-only challenge, so nothing ever ran them. 21 of the 22 Python solutions pass their own test cases in Pyodide; `left-right-given-largest` does not (it divides with `/` and prints `32.0`), and it is not linked from any lesson
- Pyodide is about 6 MB to download on first visit (3.6 MB wasm and 2.5 MB stdlib, gzipped), then cached. An infinite loop costs 5 s per test case plus an interpreter restart: 17 s for a three-case challenge
- printables: image-based resources render correctly; `binary-to-alphabet`, an HTML-type resource, comes out unstyled because the Bootstrap print CSS (built by gulp upstream) is not part of the offline run. Three generators use unseeded `random`
- astro-broken-links-checker does not decode percent-encoded paths, so it cannot check links to the PDFs when they are served locally; local builds point at the preview server's origin to sidestep it
